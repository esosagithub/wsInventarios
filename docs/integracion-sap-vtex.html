Documentacion tecnica de envio SAP

Esta documentacion describe como se genera y envia la trama SAP para pedidos VTEX, tanto desde el script de prueba scripts/testSapXml.js como desde el servicio /picking/vtex/ventas.

Node.js Oracle SOAP SAP VTEX

Resumen

El pedido se registra en Oracle mediante el servicio VTEX. Una vez confirmada la transaccion, el sistema toma la cabecera, el detalle y los pagos desde base de datos, arma el XML SOAP y lo envia a SAP usando el servicio ZMmCreaPedidosOrl.

El script probado manualmente con node scripts/testSapXml.js VTX500107 --send ya envia correctamente la trama a SAP. El servicio automatico usa la misma logica central de armado de XML definida en src/services/sapService.js.
El envio automatico se ejecuta cuando la venta entra por el API Node /picking/vtex/ventas. Si alguien inserta directo en Oracle sin pasar por el API, Node no recibe ese evento.

Origen de datos

El valor usado en la prueba, por ejemplo VTX500107, corresponde al campo doc_ven de la tabla ventas_web. El script tambien permite buscar por pedido_web.

Busqueda de cabecera

SQL
SELECT *
FROM (
  SELECT *
  FROM ventas_web
  WHERE doc_ven = :orderKey
     OR TO_CHAR(pedido_web) = :orderKey
  ORDER BY fecha_registro DESC
)
WHERE ROWNUM = 1;

Tablas utilizadas

Tabla Uso Filtro principal
ventas_web Cabecera del pedido. De aqui sale doc_ven, pedido_web, cliente, fechas, centro, totales y direcciones. doc_ven = :orderKey o TO_CHAR(pedido_web) = :orderKey
ventas_web_detalle Lineas de productos enviadas en PtItems. pedido_web = :pedidoWeb
ventas_web_pagos Medios de pago usados para llenar PaymentDetails. pedido_web = :pedidoWeb

Ejecucion manual

El script de prueba se usa para validar una venta ya insertada en Oracle. Recibe como parametro el doc_ven o el pedido_web.

Generar XML sin enviar a SAP

PowerShell / CMD
node scripts/testSapXml.js VTX500107

Enviar XML real a SAP

PowerShell / CMD
node scripts/testSapXml.js VTX500107 --send

Envio ignorando validacion estricta SSL

PowerShell / CMD
node scripts/testSapXml.js VTX500107 --send --insecure

Diagnostico de certificado SAP

PowerShell / CMD
node scripts/testSapXml.js --cert
En la prueba manual, el script consulta ventas_web, luego obtiene pedido_web y con ese valor consulta ventas_web_detalle y ventas_web_pagos. Despues llama a buildRequest(...) para construir la trama SOAP.

Ejecucion desde el servicio

El envio automatico ocurre desde el endpoint de registro de ventas:

Endpoint produccion
POST https://ns.aseyco.com:444/picking/vtex/ventas

En el proyecto Node, ese endpoint esta registrado como /vtex/ventas en src/routes/ventasWebRoutes.js. La ruta publica incluye el prefijo /picking configurado en el servidor/proxy de produccion.

Punto exacto del disparo automatico

src/controllers/ventasWebController.js
await connection.commit();

sapService.enviarFacturaDesdeDb(docVen, pedidoWeb).catch((err) => {
  console.error(`[SAP] Error no controlado en envio automatico doc_ven=${docVen}:`, err.message);
});
El envio se dispara despues del commit(). Esto asegura que SAP tome los datos ya persistidos en Oracle, no datos en memoria antes de confirmar la transaccion.

Flujo tecnico

1
VTEX consume el API

Se llama a POST /picking/vtex/ventas con cabecera, detalle[] y pagos[].

2
Node inserta la venta

Se insertan registros en ventas_web, ventas_web_detalle y ventas_web_pagos.

3
Se confirma la transaccion

El controlador ejecuta connection.commit(). Si algo falla antes, hace rollback y no se envia a SAP.

4
Se recarga la venta desde Oracle

sapService.enviarFacturaDesdeDb(docVen, pedidoWeb) consulta las tres tablas ya confirmadas.

5
Se arma la trama SOAP

buildRequest(header, detalle, pagos) transforma los datos a la estructura requerida por SAP.

6
Se envia a SAP

El cliente SOAP llama a ZMmCreaPedidosOrlAsync usando el WSDL wsdl/z_ws_mm_crea_pedidos_ora.wsdl.

7
Se actualiza el estado

El resultado queda registrado en ventas_web.status_fi y ventas_web.mensaje_fi.

Estados SAP

El servicio actualiza la tabla ventas_web para dejar trazabilidad del envio a SAP.

Campo Valor Significado
status_fi S La venta fue enviada correctamente a SAP.
mensaje_fi Enviado a SAP correctamente Mensaje registrado cuando el envio termina sin error.
status_fi E Ocurrio un error al cargar datos o enviar la trama a SAP.
mensaje_fi Mensaje del error Detalle tecnico devuelto por Node, SOAP, SSL, Oracle o SAP. Se limita a 500 caracteres.

SQL de actualizacion

SQL
UPDATE ventas_web
SET status_fi = :statusFi,
    mensaje_fi = :mensajeFi
WHERE doc_ven = :docVen
  AND pedido_web = :pedidoWeb;

Archivos involucrados

Archivo Responsabilidad
scripts/testSapXml.js Script manual de prueba. Busca la venta por doc_ven o pedido_web, muestra el XML y opcionalmente lo envia a SAP con --send.
src/controllers/ventasWebController.js Recibe /vtex/ventas, valida datos, inserta en Oracle, confirma la transaccion y dispara el envio automatico.
src/services/sapService.js Construye la trama SAP, crea el cliente SOAP, normaliza el envelope, envia a SAP y actualiza status_fi.
config/databaseVtex.js Pool de conexion Oracle al esquema VTEX pedidos_web_vtex.
wsdl/z_ws_mm_crea_pedidos_ora.wsdl Contrato SOAP usado para generar el cliente SAP.

Validacion operativa

Validar manualmente un pedido

PowerShell / CMD
node scripts/testSapXml.js VTX500107 --send

Validar si el servicio automatico marco estado SAP

SQL
SELECT doc_ven,
       pedido_web,
       status_fi,
       mensaje_fi,
       fecha_registro
FROM ventas_web
WHERE doc_ven = 'VTX500107'
ORDER BY fecha_registro DESC;

Validar detalle y pagos asociados

SQL
SELECT *
FROM ventas_web_detalle
WHERE pedido_web = :pedidoWeb
ORDER BY linea;

SELECT *
FROM ventas_web_pagos
WHERE pedido_web = :pedidoWeb
ORDER BY linea;
Evitar ejecutar --send varias veces sobre el mismo pedido en ambientes donde SAP no sea idempotente o pueda crear documentos duplicados.
